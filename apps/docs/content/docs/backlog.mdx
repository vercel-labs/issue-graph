## Reconcile an open backlog

Reconcile finds open issues and PRs, follows their references, and suggests an action for each item. Labels are optional.

```bash
issue-graph reconcile --repo owner/repo --format markdown
issue-graph reconcile --repo owner/repo --format json --no-snapshot
```

Replace `owner/repo` with a repository you can read. The default format is Markdown in a terminal and JSON in a pipe.

The report includes counts, ordered items, supporting evidence, crawl limits, history, and next steps. Each evidence entry has a stable `code`, a `summary`, and `related` node keys for use in scripts.

## Review suggested actions

| Action | What to check |
| --- | --- |
| `verify-completed` | Current behavior and acceptance criteria for an issue linked to merged work |
| `close-superseded` | Scope coverage and contributor credit |
| `verify-superseded` | Whether the merged implementation covers the older PR |
| `resolve-competing` | Differences between competing PRs |
| `repair-closing-link` | A closing claim missing its GitHub relationship |
| `review-open-pr` | Code and checks on the latest PR head |
| `keep-linked` | Related work still active |
| `keep-untracked` | Reproduction and evidence needed to prioritize the issue |

Reconcile reads GitHub and produces this review queue. Closing issues, merging PRs, and posting comments are separate actions you perform after verification.

## Check coverage

Seed discovery paginates GitHub search up to `--max-nodes` or the 1000-result search ceiling. The default node cap is 80; you can set it from 1 to 1000. Depth, hub, concurrency, and per-node limits also apply.

Inspect `limits.seedLimitReached`, `limits.cappedOut`, and `limits.fetchFailures`. Increase the budget, re-seed a missing neighborhood, or retry an access failure as needed. See [Graph](/docs/graph) for per-node limits that apply at every node cap.

## Compare history

Reconcile saves reports under `~/.issue-graph/reconcile-owner-repo/`. History is keyed by repository so it can track changes when the open seed list changes or becomes empty.

The comparison includes added, changed, and resolved actions, plus coverage changes. Incomplete coverage suppresses unsupported new or resolved claims. `--no-snapshot` skips saving a new report but can still read an existing baseline.

## Plan the next action

```bash
issue-graph plan --repo owner/repo --format markdown
issue-graph plan --repo owner/repo --format json
```

Plan runs reconciliation and groups the results into:

- ready actions
- items needing investigation
- blocked work, including drafts, conflicts, and active related work

When coverage permits, it selects one `next` action and includes a structured `decision` for that item and its related work.

Cleanup and verification come before implementation review. Within each group, ordering uses readiness, discussion activity, and visible inbound references. The same evidence and evaluation time produce the same order.

Missing open seeds or capped neighborhoods make the queue provisional and suppress `next`. Failed neighbor references affect only the related items.

## Compare competing PRs

For competing PRs, `decision` compares draft state, reviews, mergeability, diff size, file counts, and update times. `reviewFirst` identifies a starting point for inspection. Check the code, CI, and review threads before choosing an implementation.

`blockedBy` uses visible GitHub relationships. Re-run after a merge or closure to refresh the queue.

Plan saves no snapshots. Use `--format json` for structured output; HTML export is available in graph mode. See [Command reference](/docs/reference) for output formats.
