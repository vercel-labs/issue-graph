## Start from an issue or PR

Pass a URL, or a number with `--repo`:

```bash
issue-graph 1113 --repo vercel-labs/agent-browser --depth 1 --max-nodes 12 --no-snapshot
issue-graph https://github.com/vercel-labs/agent-browser/issues/1113 --depth 1 --max-nodes 12 --no-snapshot
```

Graph is the default mode. It prints Markdown to stdout, including when piped.

For several seeds or labeled open issues:

```bash
issue-graph --seeds 64,246,281 --repo owner/repo --no-snapshot
issue-graph --label bug --repo owner/repo --prioritize --no-snapshot
```

Replace `owner/repo` and the seed numbers with your repository. Multi-seed results also show connected components.

## Read the graph

Nodes represent issues and PRs. Edges come from body and comment mentions, timeline cross-references, connected events, and closing references. Each node includes its fetched state and available author, discussion, and PR metadata. Edges retain their source and available actor/date information.

The report flags competing PRs, shared changed files, possible superseded work, and closing claims missing a GitHub closing link. Use those signals to choose what to inspect. Check the implementations and scope before recommending a closure.

`--prioritize` ranks open nodes by discussion activity: comments, participants, reactions, inbound references, and time open. The ranking is also included in JSON exports.

## Control the crawl

| Flag | Default | Effect |
| --- | --- | --- |
| `--depth N` | `2` | Same-repository recursion from depth-zero seeds |
| `--max-nodes N` | `80` | Total node cap, from 1 to 1000 |
| `--hub-threshold N` | `12` | Fetch a non-seed node but stop expanding it above this reference count |
| `--concurrency N` | `4` | Concurrent node requests, from 1 to 32 |

Cross-repository references are fetched one hop. Explicit seeds are exempt from the hub guard; use the report's suggested re-seed command to inspect a hub.

Each node query reads up to 100 comments, 100 timeline items, 100 PR files, and 50 closing references. These connections are not fully paginated. Search-based seed discovery is limited by the node budget and GitHub's 1000-result search ceiling.

Check `cappedOut`, unfetched nodes, and unexpanded hubs when interpreting the graph. Increasing the node cap leaves the per-node limits unchanged.

## Compare snapshots

Graph mode saves history under `~/.issue-graph/`, keyed by repository and seed list. Run the same seed list again to see new nodes, state changes, and new links:

```bash
issue-graph 1113 --repo vercel-labs/agent-browser --depth 1 --max-nodes 12
```

Keep the seed order consistent for history lookup. `--no-snapshot` skips saving a new capture while still allowing comparison with existing history. Changes in access or crawl limits affect what can be compared.

## Export JSON and HTML

```bash
issue-graph 1113 --repo vercel-labs/agent-browser --depth 1 --max-nodes 12 --no-snapshot --json graph.json --html graph.html
```

`--json PATH` writes `seeds`, `depth`, `nodes`, `cappedOut`, `components`, `overlaps`, and `priorities`. Graph JSON has no `schemaVersion` field. Markdown remains on stdout.

`--html PATH` writes a self-contained explorer with filters, relationships, connected components, cleanup candidates, and an Impact view. Open it directly in your browser. The Impact view shows relationships found in the graph.

Export flags write files even with `--no-snapshot` and can overwrite existing paths. Review private results before sharing them.

## Add cluster labels

Print a task for your agent, then load its reviewed labels into an explorer:

```bash
issue-graph --seeds 64,246,281 --repo owner/repo --cluster --no-snapshot
issue-graph --seeds 64,246,281 --repo owner/repo --clusters clusters.json --html graph.html --no-snapshot
```

`--cluster` prints the task. `--clusters PATH` reads prepared labels. The input can be an array of clusters or an object containing `clusters` and `cleanup`:

```json
{
  "clusters": [
    {
      "label": "Investigate shared behavior",
      "root_cause": "Hypothesis to verify",
      "members": [{ "key": "owner/repo#64", "verdict": "inspect" }]
    }
  ],
  "cleanup": [{ "key": "owner/repo#64", "text": "Verify scope before acting" }]
}
```

See [Agents and skills](/docs/agents) for running an external agent and [Permissions and privacy](/docs/security) for handling private data.
