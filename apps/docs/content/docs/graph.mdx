## Start from an issue or PR

Pass an item as `owner/repo#123`, a URL, or a number inside a GitHub checkout:

```bash
issue-graph graph vercel-labs/agent-browser#1113 --depth 1 --budget 12 --no-save
issue-graph graph https://github.com/vercel-labs/agent-browser/issues/1113 --depth 1 --budget 12 --no-save
```

`graph` prints a formatted report in a terminal and Markdown when piped.

For several seeds, or to rank labeled open issues:

```bash
issue-graph graph 64 246 281 --repo owner/repo --no-save
issue-graph rank owner/repo --label bug --no-save
```

Replace `owner/repo` and the seed numbers with your repository. Multi-seed results also show connected components.

## Read the graph

Nodes represent issues and PRs. Edges come from body and comment mentions, timeline cross-references, connected events, and closing references. Each node includes its fetched state and available author, discussion, and PR metadata. Edges retain their source and available actor/date information.

The report flags competing PRs, shared changed files, possible superseded work, and closing claims missing a GitHub closing link. Use those signals to choose what to inspect. Check the implementations and scope before recommending a closure.

`rank` orders open nodes by discussion activity: comments, participants, reactions, inbound references, and time open. Graph JSON exports also include the ranking in `priorities`.

## Control the crawl

| Flag | Default | Effect |
| --- | --- | --- |
| `--depth N` | `2` | Same-repository recursion from depth-zero seeds |
| `--budget N` | `80` for explicit items; `1000` for a repository | Total node cap, from 1 to 1000 |
| `--hub-threshold N` | `12` | Fetch a non-seed node but stop expanding it above this reference count |
| `--concurrency N` | `4` | Concurrent node requests, from 1 to 32 |

Cross-repository references are fetched one hop. Explicit seeds are exempt from the hub guard; use the report's suggested re-seed command to inspect a hub.

Each node query reads up to 100 comments, 100 timeline items, 100 PR files, and 50 closing references. These connections are not fully paginated. Search-based seed discovery is limited by the node budget and GitHub's 1000-result search ceiling.

Check `cappedOut`, unfetched nodes, and unexpanded hubs when interpreting the graph. Increasing the node cap leaves the per-node limits unchanged.

## Compare snapshots

Graph mode saves history under `~/.issue-graph/`, or `ISSUE_GRAPH_HOME` when set, keyed by repository and seed list. Run the same seed list again to see new nodes, state changes, and new links:

```bash
issue-graph graph vercel-labs/agent-browser#1113 --depth 1 --budget 12
```

Keep the seed order consistent for history lookup. `--no-save` skips saving a new capture while still allowing comparison with existing history. Changes in access or crawl limits affect what can be compared.

## Export JSON and HTML

```bash
issue-graph graph vercel-labs/agent-browser#1113 --depth 1 --budget 12 --no-save -o graph.json -o graph.html
```

`-o PATH.json` writes `seeds`, `depth`, `nodes`, `cappedOut`, `components`, `overlaps`, and `priorities`. Graph JSON has no `schemaVersion` field. Markdown remains on stdout.

`-o PATH.html` writes the static Next.js dashboard with Explore, Impact, Swarm, and Rank views. Open the HTML directly in your browser; no Next server is needed. Keep its sibling `_next/` assets and `font-LICENSE.txt` when moving it. Impact shows relationships found in the graph, not proven causality.

To query the same data from the CLI, export a dashboard without `--no-save`, or start with `issue-graph open owner/repo`. Then use `query` for shared filters, scoring, exact links, and replay. See [Dashboard and saved queries](/docs/dashboard).

Export paths write files even with `--no-save` and can overwrite existing paths. Review private results before sharing them.

## Add cluster labels

Print a task for your agent, then load its reviewed labels into an explorer:

```bash
issue-graph cluster owner/repo
issue-graph cluster owner/repo --apply clusters.json
issue-graph graph 64 246 281 --repo owner/repo --clusters clusters.json -o graph.html --no-save
```

`cluster` saves the run and prints the task; `--apply` loads your agent's answer into that run's dashboard. `--clusters PATH` reads prepared labels into any graph export. The input can be an array of clusters or an object containing `clusters` and `cleanup`:

```json
{
  "clusters": [
    {
      "label": "Investigate shared behavior",
      "root_cause": "Hypothesis to verify",
      "members": [{ "key": "owner/repo#64", "verdict": "inspect" }]
    }
  ],
  "cleanup": [{ "key": "owner/repo#64", "text": "Verify scope before acting" }]
}
```

See [Agents and skills](/docs/agents) for running an external agent and [Permissions and privacy](/docs/security) for handling private data.
