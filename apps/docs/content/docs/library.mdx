## Install

```bash
npm install issue-graph@latest
```

The package provides ESM imports and TypeScript declarations. It declares Node.js 20 or later. The core has no Node built-in imports; collectors use the transport you supply.

| Import | Runtime requirements |
| --- | --- |
| `issue-graph` | Core collectors, classification, ranking, and rendering |
| `issue-graph/transport/shell` | Node-compatible child processes and authenticated `gh` |
| `issue-graph/transport/http` | `fetch` and a GitHub token |
| `issue-graph/transport/twg` | Node-compatible child processes and authenticated customer `twg` |

CLI snapshot storage and the headless agent runner are separate from the core exports. Your application manages persistence and agent execution.

## Crawl with HTTP

Store the token in your server's environment:

```ts
import {
  classify,
  crawl,
  fileOverlaps,
  fillMentionedBy,
  makeFetchNode,
  prioritize,
} from "issue-graph";
import { httpTransport } from "issue-graph/transport/http";

const token = process.env.GITHUB_TOKEN;
if (!token) throw new Error("GITHUB_TOKEN is required");

const repo = { owner: "vercel-labs", repo: "portless" };
const transport = httpTransport({ token });
const { nodes, cappedOut } = await crawl(
  [{ ...repo, number: 427 }],
  {
    maxDepth: 1,
    maxNodes: 80,
    hubThreshold: 12,
    concurrency: 4,
    primaryRepo: repo,
  },
  makeFetchNode(transport),
);

classify(nodes);
fillMentionedBy(nodes);
const priorities = prioritize(nodes, new Date());
const overlaps = fileOverlaps(nodes);
const unfetched = [...nodes.values()].filter((node) => !node.fetched);
console.log({ priorities, overlaps, cappedOut: [...cappedOut], unfetched });
```

Include `cappedOut` and unfetched nodes in your results. The [graph crawl limits](/docs/graph) apply to library calls too.

`httpTransport` uses GitHub's public API host. Its `token` option accepts a string or a synchronous/asynchronous resolver. It handles bounded retries and exposes these options:

| Option | Default |
| --- | --- |
| `timeoutMs` | 20000 |
| `maxRetries` | 3 retries after the initial attempt |
| `concurrency` | 5 transport requests |
| `maxBackoffMs` | 60000 |
| `userAgent` | `issue-graph` |

Transport concurrency is separate from crawl concurrency. Handle exhausted retries and report incomplete nodes.

## Use GitHub CLI authentication

In a Node-compatible process, replace the HTTP transport with:

```ts
import { shellTransport } from "issue-graph/transport/shell";

const transport = shellTransport();
```

Pass this transport to `makeFetchNode`. It runs `gh api` with the process's GitHub CLI credentials and requires child-process support. Authentication and retries are handled by `gh`.

## Crawl Jira through TWG

The Node-only TWG client runs the public `twg jira workitem get` command with direct JSON output. The runtime-agnostic core normalizes work items and preserves failed reads as explicit nodes:

```ts
import {
  buildJiraReport,
  crawlGraph,
  fetchJiraNode,
  jiraDepthForEdge,
  jiraNodeKey,
} from "issue-graph";
import { twgJiraClient } from "issue-graph/transport/twg";

const issueKey = "PROJ-123";
const site = "example";
const limits = {
  maxDepth: 2,
  maxNodes: 80,
  hubThreshold: 12,
  concurrency: 4,
};
const reader = twgJiraClient();
const result = await crawlGraph(
  [{ key: jiraNodeKey(issueKey) }],
  { ...limits, depthForEdge: jiraDepthForEdge(issueKey) },
  (key, depth) => fetchJiraNode(reader, key, depth, site),
);
const report = buildJiraReport(issueKey, site, limits, result);
```

`twgJiraClient` accepts `binary`, `timeoutMs`, `maxBufferBytes`, or an injected `runner`. It never reads a token; the spawned TWG process resolves its own authentication. Omit `site` only when TWG has a configured default. Consumers must inspect `report.coverageComplete`, `coverage.failed`, and `coverage.cappedOut`.

## Crawl with a custom source

`crawlGraph` provides the bounded traversal engine without assuming GitHub key syntax or a transport. A collector defines canonical keys, returns a minimal `CrawlNode`, and may retain additional source fields:

```ts
import { crawlGraph, type CrawlNode, type GraphFetchNode } from "issue-graph";

interface JiraNode extends CrawlNode {
  summary: string;
  status: string;
}

declare function readJiraIssue(key: string): Promise<{
  summary: string;
  status: string;
  linkedKeys: string[];
}>;

const fetchJiraNode: GraphFetchNode<JiraNode> = async (key, depth) => {
  const issue = await readJiraIssue(key);
  return {
    key,
    depth,
    edges: issue.linkedKeys.map((linkedKey) => ({ to: `jira:${linkedKey}` })),
    summary: issue.summary,
    status: issue.status,
  };
};

const { nodes, cappedOut } = await crawlGraph(
  [{ key: "jira:PROJ-123" }],
  {
    maxDepth: 2,
    maxNodes: 80,
    hubThreshold: 12,
    concurrency: 4,
    depthForEdge: ({ edge, sourceDepth, maxDepth }) =>
      edge.to.startsWith("jira:") ? sourceDepth + 1 : maxDepth,
  },
  fetchJiraNode,
);
```

The default edge policy advances one level. `depthForEdge` can return `maxDepth` to fetch a cross-source boundary without expanding it, or `null` to leave an edge unfetched. Invalid depths fail instead of producing a misleading partial traversal. Pending nodes are always processed at the minimum known depth, so depth jumps cannot outrank nearer work under the node cap and later shorter paths lower a node before it is fetched. The node cap, hub guard, cycle deduplication, and concurrency bound match the GitHub crawler.

The packaged `issue-graph/transport/twg` adapter is one implementation of this custom-source boundary. Applications may provide another collector without changing the traversal core. The package does not install TWG or authenticate Jira on the caller's behalf.

GitHub-specific classification, PR overlap, backlog reconciliation, and rendering still expect `GraphNode`; custom-source callers should apply only analysis functions that support their node shape.

## Collect PR status

With either transport:

```ts
import { collectStatus } from "issue-graph";

const report = await collectStatus(transport, {
  repos: ["vercel-labs/portless"],
  authors: ["ctate", "Railly"],
  concurrency: 4,
  maxPages: 100,
});

console.log({ coverageComplete: report.coverageComplete, totals: report.totals });
```

Keep `coverageComplete` and per-repository coverage alongside the counts. A `null` count means unknown. See [Status and history](/docs/status) for the report fields and comparison behavior.

## Protect credentials and results

Keep GitHub tokens server-side and check access before showing private results. For Jira, preserve the TWG caller's permission boundary and never expose raw work-item output to unauthorized users. See [Permissions and privacy](/docs/security).
