## Separate the core from GitHub access

The core exports graph types, crawling, classification, ranking, rendering, reconciliation, planning, and status helpers. It does not import Node built-ins. I/O comes from the transport you pass to collectors. Importing the core does not select credentials or automatically start a crawl.

The CLI's filesystem snapshot store and headless clustering runner are not core exports. In a server integration, own your storage, authorization, retention, and agent policy explicitly.

## Install from npm

Install the published library in your consumer project:

```bash
npm install issue-graph@latest
```

The package declares Node.js 20 or later and provides ESM imports with TypeScript declarations. No source checkout or build is required. The source repository remains INTERNAL; npm availability does not grant repository access.

| Published import | Runtime requirements |
| --- | --- |
| `issue-graph` | Runtime-agnostic core; caller supplies transport and inputs |
| `issue-graph/transport/shell` | Node-compatible child processes and authenticated `gh` on `PATH` |
| `issue-graph/transport/http` | `fetch` and a GitHub token |

## Crawl with HTTP

This example uses the published npm package. Provide the token through your server's secret environment, not browser code:

```ts
import {
  classify,
  crawl,
  fileOverlaps,
  fillMentionedBy,
  makeFetchNode,
  prioritize,
} from "issue-graph";
import { httpTransport } from "issue-graph/transport/http";

const token = process.env.GITHUB_TOKEN;
if (!token) throw new Error("GITHUB_TOKEN is required");

const repo = { owner: "vercel-labs", repo: "portless" };
const transport = httpTransport({ token });
const { nodes, cappedOut } = await crawl(
  [{ ...repo, number: 427 }],
  {
    maxDepth: 1,
    maxNodes: 80,
    hubThreshold: 12,
    concurrency: 4,
    primaryRepo: repo,
  },
  makeFetchNode(transport),
);

classify(nodes);
fillMentionedBy(nodes);
const priorities = prioritize(nodes, new Date());
const overlaps = fileOverlaps(nodes);
const unfetched = [...nodes.values()].filter((node) => !node.fetched);
console.log({ priorities, overlaps, cappedOut: [...cappedOut], unfetched });
```

Retain `cappedOut` and unfetched nodes when presenting results. Successful collection does not mean every relationship was visible. The same depth, hub, and per-node limits described in [Graph](/docs/graph) apply.

`httpTransport` uses GitHub's public API host. Its `token` option accepts a string or a synchronous/asynchronous resolver. It handles bounded retries and exposes these options:

| Option | Default |
| --- | --- |
| `timeoutMs` | 20000 |
| `maxRetries` | 3 retries after the initial attempt |
| `concurrency` | 5 transport requests |
| `maxBackoffMs` | 60000 |
| `userAgent` | `issue-graph` |

Transport concurrency is separate from crawl concurrency. Handle terminal errors and incomplete node evidence; retries are not a completeness guarantee.

## Use authenticated GitHub CLI access

In a Node-compatible process, replace the HTTP transport with:

```ts
import { shellTransport } from "issue-graph/transport/shell";

const transport = shellTransport();
```

Pass this transport to `makeFetchNode` in the same crawl. It shells out to `gh api` using the credentials available to that process. It is not suitable for a browser or a runtime without child-process support. The shell transport delegates authentication and API behavior to `gh` rather than using the HTTP transport's retry settings.

## Collect status without a graph crawl

With either transport:

```ts
import { collectStatus } from "issue-graph";

const report = await collectStatus(transport, {
  repos: ["vercel-labs/portless"],
  authors: ["ctate", "Railly"],
  concurrency: 4,
  maxPages: 100,
});

console.log({ coverageComplete: report.coverageComplete, totals: report.totals });
```

Keep coverage and count provenance in your consumer. A `null` count is not zero. The collector does not make a PR merge-ready or save CLI snapshots for you. See [Status](/docs/status) for interpretation.

## Keep credentials and results scoped

Keep GitHub tokens server-side and review [permissions and privacy](/docs/security) before exposing results to other users. Public package availability does not make queried repository data public.
