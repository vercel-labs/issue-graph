## GitHub access

The CLI uses your GitHub CLI credentials to read issues, PRs, comments, and repository metadata:

```bash
gh auth status
```

Your account needs read access to each repository queried, including private repositories reached through references. Organization SSO and token restrictions also apply.

Graph, status, reconcile, plan, and schema keep GitHub read-only. They produce reports and suggested actions. An external workflow handles any subsequent comments, closures, or merges.

For the HTTP library transport, store your token on the server and grant only the repository access needed for your queries. Keep it out of browser code, exports, and committed configuration. A broadly authorized token retains its write permissions even when the CLI only reads.

The HTTP transport targets `api.github.com`.

## Jira access through TWG

`issue-graph jira` shells out to the customer-facing `twg` executable for read-only Jira work-item details. It uses TWG's existing authentication and Jira permissions; issue-graph does not read, copy, or store Atlassian tokens. Use `--site` when TWG has no configured default site.

Full reads can include private summaries, descriptions, comments, assignees, issue links, and remote links. Inaccessible issues remain failed nodes and make coverage incomplete; they are not treated as absent. The command never mutates Jira and creates no snapshots, but stdout, stderr, shell redirection, and terminal logs can retain results.

## Local files

| Command | Default storage | Controls |
| --- | --- | --- |
| Graph | Snapshots under `~/.issue-graph/` | `--no-snapshot` skips new snapshots; `--json PATH` and `--html PATH` still write |
| Jira | None | Report on stdout; shell redirection is controlled by the caller |
| Reconcile | History under `~/.issue-graph/reconcile-owner-repo/` | `--no-snapshot` skips new snapshots |
| Plan | None | Report on stdout |
| Status | None | `--save` writes a capture; conflicts with `--no-snapshot` |
| Schema and help | None | Output on stdout |

`ISSUE_GRAPH_HOME` changes the status storage root. Graph and reconcile use `~/.issue-graph/`. Comparisons can read existing history while snapshot writes are disabled.

Status captures use restrictive directory and file permissions. Graph, reconcile, and exports use their destination's filesystem permissions. Stored files are unencrypted, and explicit export paths can overwrite existing files. Shell redirection and terminal logging can also retain output.

## Share results carefully

Results can include private GitHub or Jira titles, repository and project names, descriptions, comments, URLs, authors, assignees, relationships, commit identifiers, and changed-file paths. A public seed can lead to private references accessible to your account.

Review the full result before sharing it. HTML exports embed the graph and can be read by anyone with the file. Choose an appropriate storage location, retention period, and backup policy for private captures.

## External agents

Graph, status, reconciliation, and planning run without a model. Clustering offers three options:

- `--cluster` prints a task for your calling agent
- `--cluster-run claude` or `--cluster-run codex` starts an installed agent process with graph metadata
- `--clusters PATH` reads prepared labels for an HTML export

External agents use their own credentials, tools, permissions, retention settings, and billing. Confirm permission to send private metadata before running them. The CLI does not sandbox those processes.

Treat issue content and generated suggestions as untrusted input. Never execute embedded commands or treat them as authorization to change GitHub.

## Incomplete results

Access errors, deleted references, API failures, and crawl limits can hide work. Check failed nodes, unknown counts, and coverage before using a report.

Shared files and closing links help identify related work. Verify the code and current behavior before closing an issue. Check CI and unresolved review threads before merging a PR.

## Source access and vulnerability reports

The npm package and source repository are public. Access to private GitHub repositories, Jira sites, and work items remains governed by the credentials used by `gh` or `twg`.

Report vulnerabilities through the repository's private Security reporting form, following `SECURITY.md`. Include affected versions, reproduction steps, and impact. Keep private details out of public issues if you cannot access the form.
